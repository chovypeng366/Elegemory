# 项目开发需求：Elegemory

## 你的角色

你是一名资深跨平台桌面软件工程师，同时具备优秀的 UI/UX 设计能力，精通 Rust、Tauri 2、React、TypeScript 和桌面系统 API。

请协助我从零开发一款真正能够安装运行的桌面速记软件，项目暂定名为 **Elegemory**。

你需要同时考虑代码架构、性能、桌面体验、可维护性以及未来的 macOS 和 AI 扩展能力。

不要只生成静态 UI Demo，也不要只提供伪代码。最终目标是一个具有真实剪贴板操作、本地持久化存储和快捷键支持的桌面应用。

## 1. 产品定位

Elegemory 是一款以剪贴板为入口、以时间轴为组织方式、以温暖纸张和磁吸白板为视觉语言的轻量级速记软件。

产品理念：

**记录不应当需要创建文档。**

用户应该能够在工作、学习和浏览资料时，迅速记录一段文字、一张截图或者一个待办事项，并且在未来轻松找回和复制。

核心原则：

1. 低操作成本：尽可能减少鼠标点击。
2. 本地优先：离线可用，无须注册账户。
3. 轻量运行：避免无必要的后台服务和沉重依赖。
4. 精致动效：具有纸张、磁贴的物理质感。
5. 数据可靠：自动保存，关闭软件不丢失。
6. 跨平台设计：Windows 优先，未来支持 macOS。
7. 可扩展架构：为 AI 服务预留接口。

## 2. 指定技术栈

请使用：

- Tauri 2：桌面应用框架
- Rust：系统能力和必要的后台逻辑
- React + TypeScript：用户界面
- Vite：前端构建
- Tailwind CSS：样式系统
- Motion for React：动效
- SQLite：本地数据存储
- Zustand：前端状态管理
- Lucide Icons：图标

优先采用 Tauri 官方插件完成剪贴板、全局快捷键、窗口和文件系统相关功能。

禁止使用 Electron、Next.js、Firebase、远程数据库或必须联网的后端服务。

避免引入不必要的大型富文本编辑器。

请根据实际安装的软件包版本使用正确的 Tauri 2 API，尤其注意 capabilities 权限配置。

## 3. 操作系统目标

第一阶段：Windows 10/11 x64。

后续：macOS，包括 Apple Silicon。

Windows 下采用 MSVC Rust 工具链，不要求使用 VS Code。通过 PowerShell、终端及用户现有的开发工具即可运行项目。

不同平台的剪贴板、全局快捷键和窗口管理功能需要封装为独立适配模块，不要把 Windows 特定实现直接写入 React 组件。

## 4. 窗口交互

设计两种窗口：

### A. Quick Capture：极速捕捉窗口

一个简洁、紧凑、可快速获取焦点的窗口。

建议尺寸约 420 × 300 像素，可依据内容调整。

交互要求：

- 默认通过 Ctrl + Shift + Space 唤出和隐藏。
- 快捷键可以在设置中修改。
- Windows 下支持标准 Ctrl + C / Ctrl + V。
- macOS 后续支持 Command + C / Command + V。
- 窗口弹出时自动获得焦点。
- 用户能够直接输入文字。
- 用户能够粘贴剪贴板中的截图。
- 可将截图与说明文字组合在同一条记录中。
- 支持创建待办事项。
- 自动保存，避免意外关闭造成数据丢失。
- Esc 可以关闭速记窗口，但不能丢失已经输入的内容。

不允许全局劫持 Ctrl + C 或 Ctrl + V。

### B. Memory Board：磁吸记忆白板

主界面用于管理和搜索已经保存的内容。

布局：

- 左侧：导航与内容分类。
- 顶部：搜索框、设置按钮。
- 中间：按时间分组的卡片流。
- 卡片采用响应式瀑布式或自适应网格布局。
- 支持今天、昨天、本周及历史月份分组。
- 时间轴默认按创建时间倒序显示。
- 可查看详情、编辑、复制、收藏和删除记录。

第一阶段不做复杂的自由拖动画布。磁吸效果主要通过卡片的视觉设计和进入动画实现。

## 5. 智能剪贴板功能

这是项目的核心功能，必须优先保证实际可用。

要求：

1. 能接收 Windows 系统截图工具复制的图像。
2. 能接收第三方截图工具复制到剪贴板的图片。
3. 能接收浏览器、PDF 阅读器及其他软件复制的纯文本。
4. 优先识别图片，其次识别文字。
5. 对不支持的剪贴板格式提供清晰提示。
6. 支持拖入本地 PNG/JPEG 图片作为补充功能。
7. 图片保存到应用程序本地数据目录，生成唯一文件名。
8. 图片必须持久化，重新启动应用后仍能正常显示。
9. 点击笔记的复制按钮能够重新复制文字或原始图片。
10. 支持在已有图片记录下添加文字说明。

实现时请优先检查浏览器 paste 事件中提供的 ClipboardItem/File；必要时使用 Tauri clipboard-manager 插件读取系统图片。

剪贴板图片如果以原始像素缓冲区的形式返回，必须正确编码成 PNG/JPEG 再落盘。不能将 RGBA 数据直接冒充 PNG 文件。

保留图片原始尺寸和像素信息，避免无必要的有损压缩。

不要默认持续监听、保存用户的所有剪贴板内容。第一版只在用户主动粘贴或触发捕捉操作时读取剪贴板。

## 6. 视觉设计系统

整体风格：

Warm Minimalism + Soft Skeuomorphism。

参考真实文具、纸张、照片和磁吸白板的物理质感，同时保持现代桌面应用的整洁。

建议配色：

- 主背景：#F5F0E8
- 文字纸张：#FFF5DF
- 白色图片卡：#FFFCF7
- 主要文字：#40382F
- 次要文字：#8D7E6D
- 暖棕强调色：#B8895A
- 蓝绿色磁扣：#829D97

这些颜色可以根据实际视觉效果微调，但不要采用高饱和荧光色或过多渐变。

字体使用系统字体优先，兼顾简体中文和英文排版。

纸张可以有细微的纤维纹理、温和的阴影及 0.5～2 度的视觉倾斜，但不要影响阅读。

所有交互控件应有悬停、点击和键盘焦点状态。

支持未来扩展明暗主题。

## 7. 动效要求

### 图片磁吸动画

用户粘贴一张图片后：

1. 图片卡片从上方略微偏移的位置进入。
2. 卡片伴随轻微旋转、缩放和透明度变化。
3. 到达目标位置时表现出弹簧回弹。
4. 顶部出现一枚圆形磁扣。
5. 磁扣产生轻微压下和吸附的视觉反馈。
6. 图片在短暂回弹后保持稳定。

建议使用 Motion for React 的 spring 动画完成。

动效总时间以约 350～550 毫秒为起点进行调校，不要过度夸张。

### 文字纸张动画

新增文字笔记时：

- 纸张轻轻下落。
- 有轻微旋转。
- 阴影从柔和变为稳定。
- 悬停时略微抬升。

### 待办交互

勾选时：

- 复选框显示平滑动画。
- 文字渐进划线。
- 卡片有轻微的触感反馈。

### 性能要求

优先采用 transform 和 opacity 实现动画。

避免大型图片引发频繁布局重计算。

支持 prefers-reduced-motion 系统设置。

不得因动画导致文本编辑焦点丢失、无法粘贴或卡片闪烁。

## 8. 数据模型

采用 SQLite，至少设计以下数据结构：

### notes

- id：UUID
- type：text/image/mixed/todo
- title
- created_at
- updated_at
- is_pinned
- is_favorite
- is_archived

### note_blocks

- id
- note_id
- block_type
- content
- asset_id
- sort_order
- is_completed

### assets

- id
- relative_path
- mime_type
- width
- height
- size_bytes
- created_at

### settings

保存应用程序配置、快捷键、主题等非敏感设置。

笔记与图片分开存储。数据库记录图片路径，不存放大量 Base64 图片。

时间统一采用可排序的时间戳保存，界面按照本地时区分组显示。

创建数据库迁移机制，便于未来升级。

针对创建、修改、删除和文件保存设计明确的错误处理机制。

第一阶段不要求真正调用 AI，但必须预留独立 AI Provider 接口。

预留能力：

AI 功能默认关闭，用户明确触发后才发送指定内容，避免未经授权将剪贴板资料上传到第三方服务。

模型名称、API 地址和请求配置应当可以调整，不要把 AI 业务逻辑耦合进 React 卡片组件。
